# Baseline mosquito abundance and Wolbachia replacement: simulation and plotting code

R code accompanying the manuscript **“Baseline mosquito abundance determines minimum viral blocking effect required for Wolbachia replacement as a dengue control tool”** (Chang et al.; manuscript version supplied November 2026).

## Overview

This repository contains deterministic mosquito population simulations investigating how initial *Aedes* abundance, existing source reduction, and Wolbachia-associated viral blocking influence **vectorial capacity**. The model represents aquatic and adult wild-type and Wolbachia-infected mosquitoes, density dependence, seasonality, Wolbachia fitness costs, and discrete releases. Vectorial capacity is calculated from the simulated adult populations.

Two main settings are evaluated:

1. **Existing source reduction:** Vary pre-release reductions in aquatic carrying capacity, the fraction of source reduction retained after Wolbachia introduction, and viral blocking efficacy.
2. **Initially low mosquito abundance:** Vary the initial wild-type population relative to equilibrium and compare Wolbachia replacement with no release and source reduction alone.

The repository includes simulation, vectorial-capacity calculation, and plotting scripts. The supplementary analytical derivation is not included.

## Requirements

- R 4.1 or later (for the native pipe `|>`)
- R packages: `deSolve`, `ggplot2`, `tidyverse`, `ggpubr`, `cowplot`, `patchwork`, `scales`

Install packages in R:

```r
install.packages(c(
  "deSolve", "ggplot2", "tidyverse", "ggpubr",
  "cowplot", "patchwork", "scales"
))
```

The ODE system is solved using `deSolve::ode()`. Plotting uses `ggplot2` and the additional figure-arrangement packages listed above.

## Simulation outputs and data availability

**Simulation output CSV files are intentionally not included in this GitHub repository.**
They are generated by the R simulation scripts provided here, rather than distributed
as precomputed datasets. This keeps the repository focused on reproducible source code
and avoids storing large generated files (approximately 250 MB per CSV).

To reproduce the figures:

1. Run `run_simulation_20260928.R` to regenerate the four simulation CSV datasets.
2. Keep the generated CSV files in `baseline/output/`.
3. Ensure the filenames referenced by the plotting scripts match the generated files
   (the scripts use some date-specific filenames).
4. Run the plotting scripts after applying the relative-path adjustments described below.

The `output/` directory is local destination for generated files;
they may be empty or absent in a fresh clone. Create them as needed. The generated
CSV files are not required for downloading or reviewing the source code, but **they
must be regenerated before the plotting scripts can run**.

## Running the simulations

From the `baseline/` directory, run:

```bash
Rscript run_simulation_20260928.R
```

Alternatively, open `run_simulation_20260928.R` in RStudio, set the working directory to `baseline/`, and source the script. The run can be computationally intensive because it integrates many scenarios over a 15-year daily time grid.

The simulation generates four date-stamped CSV datasets **locally**. These files are not uploaded to GitHub.
Simulation scripts may produce filenames with the current date; ensure the CSV names used by the plotting scripts match the files in `output/`.

Output files contain simulated time series and scenario identifiers. Relevant columns include `time`, `A_u`, `A_w`, `VC_u`, `VC_w`, `VC_total`, and `VC_relative` (where requested). `VC_relative` is the ratio to the selected baseline, so values below 1 indicate reduced vectorial capacity.

**Baseline definitions:** The existing-source-reduction analysis uses the mean vectorial capacity during the pre-release source-reduction period (`baseline_type = "control_period"`). The initial-population analysis uses vectorial capacity at the initial simulation time (`baseline_type = "initial"`).

## Generating the plots

The plotting scripts are located in `baseline/plot/` and read simulation results from `baseline/output/`. `plots_func.R` defines reusable plotting functions and does not export figures by itself.

| Plotting script | Purpose |
| --- | --- |
| `est_time_series_plot.R` | Time series of uninfected adults, Wolbachia-infected adults, and infection frequency for source-reduction and initial-population scenarios |
| `initial_simulation_comparison_plot_20261002.R` | Compare vectorial capacity, time to a population threshold, time to Wolbachia establishment, and intervention-period heatmaps |
| `vector_control_plot_results_20260928.R` | Source-reduction × blocking heatmaps and time to the 99% Wolbachia-frequency threshold |
| `plots_func.R` | Reusable plotting functions used by the scripts above |

From the `baseline/` working directory, run:

```r
source("plot/est_time_series_plot.R")
source("plot/initial_simulation_comparison_plot_20261002.R")
source("plot/vector_control_plot_results_20260928.R")
```

**Path setup required:** The original uploaded plotting scripts contain a machine-specific `setwd()` command and paths such as `source("plots_func.R")` and `read.csv("output_initial_blocking_results_2026-10-02.csv")`. Before running them from `baseline/`, remove the hard-coded `setwd()`, change the helper reference to `source("plot/plots_func.R")`, change parameter references to their actual path under `R/`, and prefix input CSV paths with `output/`. To save exports in `figures/` or `output/`, create those directories and update the `ggsave()` and `write.csv()` destinations. These changes are **not** automatically made by editing the README.

## Model and scenarios

The state variables are `L_u` (wild-type aquatic stage), `A_u` (wild-type adults), `L_w` (Wolbachia-infected aquatic stage), and `A_w` (Wolbachia-infected adults). The baseline carrying capacity is `K0 = 30000`, with seasonal amplitude `eta = 0.2` and period 365 days. Releases occur at 7-day intervals for one year; release sizes are calculated by the scenario functions relative to adult wild-type abundance.

The main script evaluates:

- **Existing source reduction:** 9 levels (0.1–0.9) × 4 post-release retention levels (0, 0.25, 0.5, 0.75) × 6 blocking levels (0.5–1.0): **216 combinations**.
- **Initially low abundance, Wolbachia replacement:** 10 initial population fractions (0.1–1.0) × 6 blocking levels: **60 combinations**.
- **No release:** 10 initial population fractions, blocking set to zero, release ratio set to zero.
- **Source reduction only:** 9 source-reduction levels × 11 initial population fractions (0.01 and 0.1–1.0), no Wolbachia release.

See the parameter files and `run_simulation_20260928.R` for exact settings. Model parameters and vectorial-capacity defaults are defined in `R/parameters/` and `R/calculate_vectorial_capacity_func_20260928.R`.
